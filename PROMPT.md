# Задача для Claude Code: Android-скринер б/у телефонов

Сделай Android-приложение на **Kotlin + Jetpack Compose** для быстрой проверки б/у телефона (5–10 минут) перед покупкой.
Дизайн лежит в папке `design/`: это HTML-макеты экранов. Повтори их в Compose максимально близко: цвета, отступы, скругления, иконки, порядок элементов. Сам HTML в приложение не встраивай.

> В макетах встречаются `{{ ... }}`, `<sc-if>`, `<x-dc>`, `class Component extends DCLogic`. Это служебная разметка редактора макетов: читай её как «здесь значение / условие / состояние», а не как код для переноса.

## Общие требования

- minSdk 26 (Android 8.0), targetSdk — последний стабильный.
- Работает полностью офлайн, без интернета, без SIM, без аккаунтов.
- Ставится APK с SD-карты.
- Тёмная тема по умолчанию + светлая. Переключатель — квадратная кнопка 44×44, радиус 12, в правом верхнем углу. На тёмной теме иконка ☀, на светлой ☾. Выбор темы сохраняется между запусками.
- Каждую проверку можно пропустить. В отчёте пропущенное = «пропущено», а не «ок».
- Разблокированный загрузчик и root — **не минус**, только информация в отчёте.
- Дисклеймер на главной и в отчёте: «Результат информационный и не гарантирует отсутствие скрытых дефектов».
- Без лишних зависимостей, один модуль `app`.

## Экраны (порядок)

1. **Чеклист** — `design/Checklist.dc.html`
   - Сетка плиток 2 колонки. Плитка: цветная плашка 40×40 с иконкой, название, статус, точка статуса в правом верхнем углу.
   - Основные проверки (6): Экран, Батарея, Память, Датчики, Связь (Wi-Fi, BT, GPS, NFC), Система (инфо).
   - Счётчик «N из M проверок», кнопка «Сформировать отчёт».
   - **Скрытое меню:** тап по заголовку «Проверка» открывает нижнюю панель «Дополнительные проверки» с переключателями: Камеры, Зарядка, Стресс-тест, Подлинность. Включённые появляются плитками в чеклисте и учитываются в счётчике. Состояние переключателей сохраняется.

2. **Экран** — `design/Screen.dc.html` (интерактивный образец логики)
   - Цвета на весь экран без надписей и кнопок: чёрный, белый, красный, зелёный, синий, серый. **Двойной быстрый тап** — следующий цвет.
   - Затем **тач-тест как в сервисном меню Samsung (*#0*#)**: белый фон, клетки только по периметру экрана и по двум диагоналям (крест). Непройденная клетка — белая с серой рамкой, пройденная — зелёная `#00E600`. Путь пальца рисуется чёрной линией и **остаётся** на экране. Тест пройден, когда все клетки зелёные. **Тройной быстрый тап** — выйти дальше (если не все клетки пройдены — отметить как дефект/пропуск с вопросом).
   - «Быстрый» = между тапами < 500 мс. Скрыть системные панели (immersive), держать экран включённым.
   - После теста короткий вопрос «Норм / Дефект» (пиксели, засветы, выгорание).

3. **Батарея** — `design/Battery.dc.html`. Здоровье (если система отдаёт), заряд, температура, напряжение, состояние, циклы (Android 14+, если есть), подключена ли зарядка. Нет данных — писать «нет данных».

4. **Память** — `design/Memory.dc.html`. Заявленный и реальный объём, свободно, ОЗУ. Тест записи/чтения тестового файла с проверкой контрольной суммы (ловит подделку объёма), скорость записи и чтения. Файл удалить после теста.

5. **Датчики** — `design/Sensors.dc.html`. Список строится по реально имеющимся датчикам (SensorManager). Каждый отдельной строкой, загорается «работает», когда пришли изменяющиеся данные: акселерометр, гироскоп, автоповорот, магнитометр, барометр, приближение, освещённость, датчик Холла, шагомер, ИК-порт, вибромотор (кнопка), отпечаток (BiometricPrompt), кнопки громкости и питания (ловить нажатия). Нет датчика — «нет в телефоне», не считать дефектом.

6. **Связь** — `design/Connect.dc.html`. Без SIM. Wi-Fi: скан сетей. Bluetooth: поиск устройств. GPS: число спутников. NFC без карты: модуль есть и включается; опционально — увидеть второй телефон с NFC. SIM-лоток — только наличие слотов. Запросить нужные runtime-разрешения с понятным объяснением.

7. **Система (инфо)** — `design/System.dc.html`. Модель, производитель, Android, патч безопасности, прошивка (стоковая/кастомная по признакам), статус загрузчика, признаки root, приложения-администраторы устройства. На итог не влияет.

8. **Отчёт** — `design/Report.dc.html`. Список с группами (Основное, Датчики — каждый отдельно, Связь — каждый модуль отдельно, доп. проверки). Цветные бейджи статусов. Кнопка «Сохранить на SD-карту»: файлы `report_<модель>_<дата>.txt` и `.json` через Storage Access Framework (пользователь выбирает папку на SD один раз, запомнить).

### Дополнительные (из скрытого меню)
- **Камеры** — `design/Camera.dc.html`, `design/CameraView.dc.html`. Для прошивок без штатной камеры. CameraX: запись видео со звуком, переключение камер, зум (0.6×/1×/2×/макс + ползунок), вспышка, индикатор уровня микрофона. Затем просмотр снятого на весь экран с pinch-zoom, кнопки «Норм / Дефект / Переснять». Микрофон проверяется записью, динамик — воспроизведением.
- **Зарядка** — ток (мА) и мощность в реальном времени через BatteryManager, пока подключён кабель.
- **Стресс-тест** — 2 минуты нагрузки на все ядра, график температуры батареи/CPU, предупреждение при перегреве. Кнопка «Стоп».
- **Подлинность** — сверка: заявленная модель vs реальный SoC, число ядер, разрешение экрана, объём ОЗУ/памяти. Подозрительные расхождения подсветить.

## Репозиторий и сборка

- Залей в GitHub. Красивый README на русском: что это, скриншоты (место под них), список проверок, установка с SD-карты, дисклеймер.
- В README раздел «Ответственность»: приложение даёт информационный результат, автор не отвечает за покупку/продажу устройства и скрытые дефекты. Добавь лицензию MIT.
- GitHub Actions: сборка подписанного release APK. Ключ подписи **не коммитить**: брать из GitHub Secrets (`KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`). Один и тот же ключ для всех версий, чтобы обновления ставились поверх. В README — инструкция, как создать keystore и добавить секреты.
- `.gitignore` для keystore, `local.properties`, сборочных папок.
